# Wii Sports native recompilation

## Target

This branch adds a Wii Sports game target on top of the reusable Wii runtime in this repository. The game image, extracted files, generated code and Ghidra databases are supplied and kept locally by the user. No Nintendo game data is included.

The target must preserve all five sports:

- Tennis
- Baseball
- Bowling
- Golf
- Boxing

Input requirements are keyboard, conventional gamepads, and real Wii Remote support. Boxing additionally requires real motion input, differentiated left/right punches, blocking/guarding, and Nunchuk input. These are acceptance requirements, not claims that they are already verified in this branch.

## Runtime architecture

The shared `engine/` supplies the PowerPC guest CPU state, big-endian memory, MMIO dispatch, boot setup, thread/context support, interrupts, REL module dispatch, IOS/NAND/disc services, GX command processing and rendering, DSP/audio output, SDL3 input, and Wii Remote services.

The Wii Sports-specific layer is `games/wiisports/`:

- `game.toml`: game configuration and local disc path.
- `game.cpp`: game descriptor consumed by the shared runtime.
- `analysis/symbols.csv`: optional verified address/name symbols.
- `analysis/hle_functions.csv`: explicitly approved hardware/OS replacements only.
- `extracted/`, `disc/`, and generated code: local-only data excluded from Git.

The macOS graphics path is the shared SDL3/OpenGL renderer. It does not use Mario Kart Wii game-specific runtime code.

## Important distinction: Ghidra output and native code

Ghidra is used to identify function boundaries and verified symbols. The runtime's native function ABI is `void f_XXXXXXXX(wp::Cpu&)`, generated by this repository's PowerPC lifter. Therefore the reliable integration path is:

1. Import the Wii Sports DOL into Ghidra using the Broadway/Gekko processor.
2. Export the complete function address/size list to `analysis/dol_functions.csv`.
3. Apply verified symbol names through `analysis/symbols.csv`.
4. Run this repository's lifter to generate native C++ using the runtime's CPU and memory ABI.

A prior export can be reused when its function CSV uses the expected `address,size` columns and its symbols CSV uses `address,name`. Ghidra decompiler pseudocode is not blindly linked as native code: it does not automatically satisfy the runtime ABI or PPC semantics. Existing Ghidra analysis is reusable as function metadata and symbols, while the lifter generates the runtime-compatible C++ functions.

## macOS setup

Requirements:

- Apple Xcode Command Line Tools.
- CMake, Ninja, Python 3 and Git.
- `nodtool` available on `PATH` for disc extraction.
- Ghidra 12 with the GameCube Loader and the `PowerPC:BE:32:Gekko_Broadway` processor language.
- A legally obtained Wii Sports disc dump supplied by the user.

On the Mac used for this project, the default Ghidra location is `~/Tools/ghidra_12.1.4_PUBLIC`. Override it with `GHIDRA_HOME` when needed.

Place the user's disc dump at `games/wiisports/disc/wiisports.rvz`, or pass another path to `tools/build_wii_sports_macos.sh`. If you already have a complete extracted Wii Sports filesystem, place it under `games/wiisports/extracted/`; the helper will not require `nodtool` or a second extraction.

Run:

```sh
bash tools/build_wii_sports_macos.sh
```

The script extracts the disc only when no extracted filesystem exists. It reuses a non-empty `analysis/dol_functions.csv` export and the supplied symbol CSVs by default; set `WII_SPORTS_REIMPORT_GHIDRA=1` to rerun headless Ghidra. It then translates the DOL and REL modules, recompiles DSP code, configures the native target, builds and runs `build/out/wiisports`.

## Processor Interface MMIO

The shared runtime now models the PI interrupt cause register at `0xCC003000` and interrupt mask register at `0xCC003004`, including cause write-one-to-clear behavior, mask readback and 16-bit read views. The tests cover these register accesses. The full relationship between each emulated device interrupt, PI cause bits and guest exception delivery still needs to be validated against Wii Sports; this register model does not claim that interrupt aggregation is complete.

## Compatibility and validation

A successful compile is not proof of a playable game. Runtime bring-up must validate, in order:

1. DOL entry and function dispatch.
2. OS context switching, threads, interrupts and retrace timing.
3. Disc and filesystem reads, NAND/save behavior, and dynamically linked REL modules.
4. GX FIFO/MMIO handling and rendered menus.
5. DSP/audio output.
6. Controller mapping and motion data.
7. Each of Tennis, Baseball, Bowling, Golf and Boxing.

Unknown MMIO must be implemented according to the register/device behavior; it must not be silently swallowed. An unresolved guest address must be resolved to a translated DOL/REL function or a correctly justified runtime service. Do not paper over errors by suppressing the diagnostics.

The inherited engine contains generic Wii support, but Wii Sports-specific behavior, every MMIO path used by this title, its module set, its controller mappings, Nunchuk handling and the five sports still require testing against the user's own dump. This branch is an integration foundation, not a claim of completed gameplay compatibility.
